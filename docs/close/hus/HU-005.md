# HU-005 — Integrar tarjeta SonarQube en Dashboard con datos mock

**Como** lider tecnico  
**Quiero** ver la tarjeta de SonarQube en el dashboard de salud tecnica  
**Para** revisar rapidamente el estado de calidad del proyecto sin abrir SonarQube

---

## Dependencias

- Requiere: HU-004 (cascarón UI del dashboard general)
- Requiere: layout y card de integraciones ya renderizados en `narnia/`
- No requiere conexion real con SonarQube en esta iteracion

---

## Contexto / Notas

- Esta HU implementa solo la integracion visual y de datos mock de SonarQube.
- La conexion real con SonarQube queda para una HU posterior.
- Debe respetar arquitectura por capas (Presentation -> Domain <- Infrastructure), sin romper contratos.
- En esta HU, el dashboard no puede romperse si la futura integracion falla.

---

## Diseño (OBLIGATORIO si hay UI)

Referencias:
- Diseño base dashboard: `docs/close/design/dashboard_de_salud_tecnica_general/screen.png`
- Código de referencia visual: `docs/close/design/dashboard_de_salud_tecnica_general/code.html`

Reglas:
- Mantener estilo y jerarquia visual de la tarjeta de integracion.
- La tarjeta debe mostrar claramente proveedor, estado y metricas clave.
- La tarjeta debe indicar a que proyecto pertenece la informacion.

---

## Alcance

Incluye:
- Tarjeta SonarQube con datos mock en dashboard general.
- Estados visuales para `healthy`, `warning`, `critical`, `unknown`.
- Render de metricas mock:
  - `qualityGateStatus`
  - `coverage`
  - `bugs`
  - `vulnerabilities`
- Fallback visual cuando no haya datos (`unknown`) sin romper la UI.

No incluye:
- Llamadas reales a SonarQube API.
- Manejo de tokens/credenciales.
- Persistencia o cache.

---

## Criterios de aceptación (Given / When / Then)

### 1) Render de tarjeta SonarQube

- **Dado** el usuario en `/dashboard/technical-health`
- **Cuando** se renderiza la seccion de integraciones
- **Entonces** se visualiza una tarjeta `SonarQube` con nombre de proyecto y estado actual

### 2) Metricas mock visibles

- **Dado** un dataset mock valido de SonarQube
- **Cuando** se renderiza la tarjeta
- **Entonces** se muestran `qualityGateStatus`, `coverage`, `bugs` y `vulnerabilities` en formato legible

### 3) Semaforo de estado entendible

- **Dado** un estado de salud mock (`healthy`, `warning`, `critical`)
- **Cuando** el usuario visualiza la tarjeta
- **Entonces** el estado se representa con señal visual clara y consistente

### 4) Comportamiento ante ausencia de datos

- **Dado** un escenario sin datos mock o con error simulado
- **Cuando** se renderiza la tarjeta
- **Entonces** se muestra estado `unknown` con mensaje amigable y el dashboard sigue operativo
