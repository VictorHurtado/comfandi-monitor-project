# HU-008 — Mostrar métricas SonarQube (Coverage, Bugs, Vulnerabilities) en la tarjeta

**Como** líder técnico  
**Quiero** ver en la tarjeta de SonarQube el porcentaje de cobertura, la cantidad de bugs y de vulnerabilidades  
**Para** comparar de un vistazo la calidad del código del proyecto sin entrar a Sonar

---

## Dependencias

- Requiere: HU-007 (configuración Sonar por proyecto y tarjeta con semáforo en dashboard)
- La tarjeta Sonar ya existe y muestra Quality Gate; esta HU añade las cuatro métricas acordadas en la misma tarjeta.

---

## Contexto / Notas

- Proyecto en contexto: mismo que HU-007 (por ahora **afiliaciones**; datos por proyecto seleccionado).
- Las **cuatro métricas** acordadas para Sonar en el dashboard:
  1. **Quality Gate** (passed/failed) — ya en HU-007 (semáforo).
  2. **Coverage** (%).
  3. **Bugs** (cantidad).
  4. **Vulnerabilities** (cantidad).
- Si alguna métrica no viene en la respuesta de Sonar o falla: mostrar texto tipo "sin dato" de forma consistente con el design system (no confundir con error de conexión).
- Al refrescar la página, los datos deben volver a cargarse correctamente (sin estado corrupto ni caché incorrecta que impida ver datos).

---

## Diseño (OBLIGATORIO si hay UI)

- Misma tarjeta que en HU-007; añadir bloques o filas para: Coverage (%), Bugs (número), Vulnerabilities (número).
- Coverage en porcentaje, fácil de leer (ej. "72 %" o "72%" con estilo destacado).
- Bugs y Vulnerabilities en la misma tarjeta para comparar rápido (ej. dos números o etiquetas claras).
- Estado "sin dato": texto corto y neutro (ej. "—" o "sin dato"), sin parecer error. Usar tokens `brand-*` y tipografía del tema.

---

## Alcance

**Incluye:**

- **Domain**: ampliar modelo de Sonar (ej. `SonarProjectStatus`) con `coverage?: number`, `bugs?: number`, `vulnerabilities?: number`; si la API no devuelve un valor, el modelo debe permitir `undefined` o null y la UI mostrar "sin dato".
- **Infrastructure**: en la llamada a la API de Sonar, solicitar/mapear las métricas (coverage, bugs, vulnerabilities) además del Quality Gate; mapear DTO → modelo de dominio.
- **BFF**: el endpoint de Sonar por proyecto debe devolver estas métricas junto al Quality Gate.
- **Presentation**: en la tarjeta Sonar, mostrar Coverage (%), Bugs y Vulnerabilities; cuando no hay valor, mostrar "sin dato" (o convención acordada) de forma consistente.
- Comportamiento al refrescar: al recargar la página, se vuelven a solicitar los datos al BFF y se muestran correctamente (sin dependencia de estado previo erróneo).

**No incluye:**

- Cache o TTL de actualización (HU-009).
- Cambios en el Quality Gate o en la configuración de env (ya en HU-007).

---

## Criterios de aceptación (Given / When / Then)

### 1) Coverage en porcentaje y fácil de leer

- **Dado** un proyecto con datos de Sonar que incluyen cobertura
- **Cuando** el usuario ve la tarjeta de Sonar en el dashboard
- **Entonces** se muestra el valor de cobertura en porcentaje (ej. "72 %") de forma clara y legible

### 2) Bugs y Vulnerabilities en la misma tarjeta

- **Dado** un proyecto con datos de Sonar que incluyen bugs y vulnerabilidades
- **Cuando** el usuario ve la tarjeta de Sonar
- **Entonces** se muestran la cantidad de bugs y la cantidad de vulnerabilidades en la misma tarjeta para comparar rápido

### 3) Sin dato mostrado de forma clara

- **Dado** que una métrica (Coverage, Bugs o Vulnerabilities) no está disponible en la respuesta o no aplica
- **Cuando** se renderiza la tarjeta
- **Entonces** se muestra un texto breve tipo "sin dato" (o "—") que no parezca un error y sea consistente con el resto de la UI

### 4) Datos correctos al refrescar

- **Dado** que el usuario tiene el dashboard abierto
- **Cuando** actualiza la página (F5 o recargar)
- **Entonces** los datos de Sonar se vuelven a cargar y se muestran correctamente en la tarjeta
