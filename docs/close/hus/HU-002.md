# HU-002 — Configurar Tailwind y Theme base (modo claro)

**Como** equipo frontend de Narnia  
**Quiero** configurar Tailwind CSS y el theme base del proyecto en modo claro  
**Para** estandarizar la UI y permitir que los equipos construyan pantallas sobre una base visual comun

---

## Dependencias

- Requiere: HU-001 (bootstrap de proyecto base)
- Requiere: definicion de tokens visuales base (`brand-*`, tipografia y escalas)
- Requiere configuración previa: Tailwind CSS integrado en Next.js

---

## Contexto / Notas

- Esta HU es fundacional de UI para todas las HUs visuales siguientes.
- Debe respetar `docs/close/01_arquitectura.md` y mantener Presentation separada de Domain/Infrastructure.
- El alcance es solo configuracion y base de estilos; no incluye logica de negocio.
- **Modo oscuro queda fuera de alcance por ahora**; trabajar unicamente con **tema claro**.

## Alcance

Incluye:
- Configurar `tailwind.config` con tokens de color base (`brand-*`) para modo claro.
- Definir tipografia base (`font-outfit` o la definida como oficial del proyecto).
- Definir escala de texto y tamaños base de componentes.
- Definir tokens de border radius, sombras y estados comunes (hover/focus/disabled).
- Configurar estilos globales iniciales (`globals.css` equivalente) para tema claro.
- Documentar tokens base para uso por los equipos.

No incluye:
- Implementacion de modo oscuro.
- Construccion de pantallas funcionales.
- Integracion con APIs o datos reales.

## Criterios de aceptación (Given / When / Then)

### 1) Theme base disponible

- **Dado** el proyecto Narnia inicializado
- **Cuando** se inspecciona la configuracion de Tailwind
- **Entonces** existen tokens base del theme claro y son reutilizables desde componentes

### 2) Consistencia visual inicial

- **Dado** componentes de prueba de la UI
- **Cuando** aplican clases de Tailwind del proyecto
- **Entonces** usan tokens del theme y no valores hardcodeados fuera de convención

### 3) Modo claro unicamente

- **Dado** la HU-002 implementada
- **Cuando** se valida el alcance
- **Entonces** la configuracion se limita a tema claro y no introduce comportamiento dark mode

## Reglas técnicas

### Arquitectura
- El theme y estilos viven en Presentation/estilos globales.
- Domain e Infrastructure no deben depender de Tailwind ni de UI tokens.

### UI (si aplica)
- UI con **Tailwind CSS**.
- **Usar SIEMPRE tokens `brand-*`** del tema.
- Tipografia oficial definida en theme.
- Evitar colores hex inline en componentes.

### Dependencias / Paquetes
- No agregar paquetes adicionales de estilos fuera de Tailwind/PostCSS/autoprefixer si no estan aprobados.
- Si aparece error 403/conectividad:
  1) Detenerse
  2) Pedir dominios requeridos
  3) Explicar por que se requieren
  4) No continuar
