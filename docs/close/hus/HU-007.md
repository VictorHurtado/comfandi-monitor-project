# HU-007 — Configuración SonarQube por proyecto y tarjeta con semáforo en dashboard

**Como** líder técnico  
**Quiero** que el monitor consulte SonarQube por proyecto y muestre una tarjeta con estado de calidad (semáforo) en el dashboard  
**Para** ver de un vistazo si el proyecto cumple el Quality Gate sin entrar a Sonar

---

## Dependencias

- Requiere: HU-004 (cascarón UI del dashboard) y tarjetas de integraciones en `narnia/`
- Requiere: flujo de proyecto seleccionado desde `/project-selector` (contexto de proyecto)
- Requiere: variables de entorno para Sonar (ver abajo). Si no están configuradas o Sonar falla, la tarjeta se muestra con estado "no disponible" sin romper el dashboard.

---

## Contexto / Notas

- **Proyecto en contexto**: en el monitor por ahora solo existe el proyecto **afiliaciones** (en Jira corresponde al proyecto **PSA** — Sucursal Afiliaciones: <https://comfanditi.atlassian.net/jira/software/c/projects/PSA/boards/794/backlog>). La tarjeta Sonar debe estar asociada al proyecto seleccionado y mostrar datos de ese proyecto.
- **Configuración por proyecto**: mismo patrón que Jira. Variables de entorno para acceso a Sonar (ver Alcance). Mapeo proyecto monitor → clave en Sonar vía `SONAR_PROJECT_KEY_MAP` (ej. `{"afiliaciones":"clave-sonar-del-proyecto"}`).
- Arquitectura: Domain define contrato del repositorio/servicio Sonar; Infrastructure implementa cliente HTTP a la API de SonarQube/SonarCloud; Presentation consume Use Case; BFF expone endpoint por proyecto.
- Si la integración falla o no está configurada: tarjeta visible con semáforo en estado "unknown" o "no disponible", mensaje breve no técnico; **nunca** romper el layout ni mostrar stack traces.

---

## Diseño (OBLIGATORIO si hay UI)

- Consistente con el resto de tarjetas de integración (ej. Jira, GitHub). La tarjeta debe indicar **a qué proyecto** pertenecen los datos (ej. "SonarQube — Afiliaciones").
- **Semáforo**: verde = Quality Gate passed, rojo = failed, amarillo/neutro = unknown o sin dato. Usar tokens `brand-*` del tema en `tailwind.config.ts`.
- Referencias: `docs/close/design/dashboard_de_salud_tecnica_general/` si existe; código de referencia de `IntegrationCardsGrid` y `HealthStatusCard`.

## Alcance

**Incluye:**

- **Variables de entorno** (documentar en `narnia/.env.example` y en esta HU):
  - `SONAR_BASE_URL`: URL base de SonarQube o SonarCloud (ej. `https://sonarcloud.io` o URL on-premise).
  - `SONAR_TOKEN`: token de autenticación para la API (no hardcodear; solo en env).
  - `SONAR_PROJECT_KEY_MAP`: JSON que mapea slug del proyecto en el monitor → clave del proyecto en Sonar (ej. `{"afiliaciones":"org_key"}` o la key exacta del proyecto en Sonar).
- **Domain**: modelo (ej. `SonarProjectStatus`) con al menos `qualityGate: 'passed' | 'failed' | 'unknown'`, `projectKey`, `projectSlug`; contrato del repositorio o servicio que obtiene estado Sonar por proyecto.
- **Infrastructure**: implementación que llama a la API de Sonar (Quality Gate) usando las variables de entorno; mapeo proyecto actual (slug) → clave Sonar vía `SONAR_PROJECT_KEY_MAP`; manejo de errores → estado "unknown" sin lanzar al usuario.
- **BFF**: endpoint (ej. `GET /api/v1/integrations/sonar` con query/header de proyecto, o `GET /api/v1/projects/[slug]/integrations/sonar`) que devuelva estado de Sonar para el proyecto en contexto.
- **Presentation**: tarjeta Sonar en el dashboard que muestre semáforo (Quality Gate) e identifique el proyecto; si Sonar no responde o no está configurado, mostrar estado "no disponible" / "sin dato" sin romper la página.

**No incluye:**

- Métricas detalladas (Coverage, Bugs, Vulnerabilities) — ver HU-008.
- Actualización automática / cache TTL — ver HU-009.

## Criterios de aceptación (Given / When / Then)

### 1) Tarjeta visible con semáforo por proyecto

- **Dado** un proyecto seleccionado (ej. afiliaciones) y Sonar configurado correctamente
- **Cuando** el usuario abre el dashboard de salud técnica
- **Entonces** se muestra la tarjeta de SonarQube con semáforo (verde/rojo/amarillo según Quality Gate) y se identifica el proyecto (ej. "Afiliaciones")

### 2) Configuración por variables de entorno

- **Dado** el archivo de entorno con `SONAR_BASE_URL`, `SONAR_TOKEN` y `SONAR_PROJECT_KEY_MAP` definidos para el proyecto
- **Cuando** el BFF recibe una petición de estado Sonar para ese proyecto
- **Entonces** se usa el mapeo para resolver la clave Sonar y se consulta la API sin credenciales en código

### 3) Degradación graceful si Sonar falla o no está configurado

- **Dado** Sonar no configurado, caído o con error
- **Cuando** el usuario abre el dashboard
- **Entonces** la tarjeta Sonar se muestra con estado "no disponible" o "sin dato" y semáforo en estado neutro; el resto del dashboard sigue funcionando
